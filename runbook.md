# Coin-Ops Infrastructure Runbook

This runbook is for operators of the infra-only repository. Application images are already published to GHCR and are treated as deployment inputs.

## Daily Setup

```bash
cd /home/notebook/projects/coin-ops
source local/generated-env.sh
make tf-check-backend
```

If generated env files are missing, run the matching Terraform bootstrap helper first:

```bash
terraform/bootstrap-gcp.sh
terraform/bootstrap-aws.sh
terraform/bootstrap-azure.sh
```

## Terraform Flow

```bash
cd terraform
terraform fmt -check -recursive
terraform validate
terraform plan
terraform apply
```

`terraform/backend.active.tf` is generated by bootstrap scripts and is the explicit backend selector. Do not commit it.

## VM Compose Deploy Flow

```bash
cd /home/notebook/projects/coin-ops
make provision
make deploy
```

The deploy playbook renders `deploy/compose/*.compose.yaml` templates onto hosts and pulls GHCR images. It does not build app containers locally.

## k3s Platform Flow

```bash
cd /home/notebook/projects/coin-ops
make k3s-cluster
make k3s-platform
make k3s-homepage
make k3s-coinops
```

The local kubeconfig and helper scripts are generated under `ansible/artifacts/`. They are sensitive and must not be committed. For an operator shell, run:

```bash
source ansible/artifacts/k8s-operator-env.sh
kubectl get nodes
```

## Runtime SQL

The retained PostgreSQL bootstrap assets live under:

- `deploy/sql/history/schema.sql`
- `deploy/sql/runtime/*.sql`

VM Compose deploy copies them to the backend host before service startup. k3s deploy mounts them into the CNPG bootstrap job. They are infrastructure assets, not application source.

## Image Inputs

Default images are resolved by Ansible from `terraform/config/deploy.json`:

- `coin-ops-proxy`
- `coin-ops-history-api`
- `coin-ops-history-consumer`
- `coin-ops-ui`
- `coin-ops-postgres-runtime`

Override with `IMAGE_REGISTRY`, `IMAGE_TAG`, or `POSTGRES_RUNTIME_IMAGE` only for deliberate operator testing or releases.

## Rollback Runtime Mode

`RUNTIME_BACKEND=external` keeps RabbitMQ and Redis available for rollback. The normal runtime is PostgreSQL-backed `RUNTIME_BACKEND=postgres`.

## Destroy and Repair

Use `terraform/full-destroy.sh --yes-really-destroy-stateful` for deliberate full teardown. It works from a temporary Terraform copy and leaves checked-in files untouched. Use `terraform/repair-refresh.sh` for refresh-only state repair when secret backend reads or provider cleanup need isolation.

GCS backup provisioning, status checks, and test-namespace restore drills are documented in docs/k3s-cnpg-backups.md.
