# k3s_kubeconfig_access

Resolves the kubeconfig path used by `kubernetes.core` and Helm-based `k3s`
application roles.

This role now supports two execution models:

- local operator mode: use the direct kubeconfig artifact generated by `k3s_postcheck`
  on the operator machine
- remote node mode: use the native `/etc/rancher/k3s/k3s.yaml` on a k3s server

Local operator mode is the preferred path for cluster application playbooks such
as Homepage, Headlamp, and Coin-Ops. Remote node mode remains available as a
fallback for roles that still need to run on cluster hosts.
